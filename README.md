# node-kit — ноды и мосты Remnawave: поставить, разогнать, не дать упасть

> Впервые? → **[Мост с нуля за 5 минут](docs/START-HERE.md)**.
> Уже всё работает и страшно трогать? → **[Что меняет каждый скрипт и как отменить](docs/SAFETY.md)**.

Семь bash-скриптов без зависимостей, выросшие из эксплуатации нескольких десятков нод и
мостов. Каждый делает одну вещь, печатает одну понятную строку результата и умеет отменять
себя.

| скрипт | что делает | результат |
|---|---|---|
| `install-node.sh` | нода или мост на чистом Ubuntu/Debian одной командой: docker, BBR, `.env`, compose, для моста — geodata с проверкой размера | `RESULT: контейнер=[Up] xray=26.3.27 порт 3000 слушает=да` |
| `tune-net.sh` | BBR + большие TCP-буферы | хоп мост → нода: **87 → 600 Мбит/с** одним потоком (cubic/208 КБ → BBR/64 МБ) |
| `tune-resilience.sh` | conntrack по памяти, очередь приёма, watchdog, авторебут при панике, earlyoom, своп для малых серверов | нода не зависает молча и не роняет соединения под нагрузкой |
| `geodata-update.sh` | обновление списков маршрутизации на мосту с проверкой, что xray поднялся, и откатом | свежие списки без риска положить мост; таймер раз в неделю |
| `probe-speed.sh` | полоса ноды: 8 потоков, Европа и РФ, **минус фон клиентов** | `Европа 534 Мбит/с (фон клиентов 118)` |
| `probe-steal.sh` | steal time — сколько CPU забирает гипервизор | `steal 31%` — хостер перепродал сервер |
| `health.sh` | одна строка здоровья: cpu, steal, ретрансмиты, память, xray, conntrack, переполнения очереди, трафик | для ежедневного обхода флота |
| `fleet.sh` | любой из скриптов — на списке серверов по ssh | `./fleet.sh nodes.txt health.sh` |

## Три числа, ради которых это написано

- **87 → 600 Мбит/с.** Один поток через межконтинентальный линк упирается в окно TCP.
  `tune-net.sh` включает BBR и буферы 64 МБ — скорость хопа мост → нода выросла в семь раз
  на тех же серверах.
- **58 668 из 65 536.** Таблица conntrack на мосту с 10 тыс. соединений заполнена на 90% ещё
  днём; вечером ядро начнёт **молча** выбрасывать новые соединения — «VPN тупит», а в логах
  пусто. `tune-resilience.sh` ставит лимит по памяти.
- **5,7 млн переполнений** очереди приёма на ноде за неделю: при 3–7 тыс. соединений
  `somaxconn=4096` не хватает, клиент заходит со второй попытки. Тот же скрипт.

И одно наблюдение: `ping` идёт, `load` низкий, панель довольна — а нода отдаёт 10 Мбит,
потому что хостер душит её под нагрузкой или гипервизор забирает 30% CPU. Это ловят
`probe-speed.sh` и `probe-steal.sh`, а не мониторинг порта.

## Быстрый старт

```bash
git clone https://github.com/ponoroshca/remnawave-node-kit.git && cd remnawave-node-kit
```

Новый мост (ключ — из карточки ноды в панели, см. [START-HERE](docs/START-HERE.md)):

```bash
sudo ./install-node.sh --secret <SECRET_KEY> --bridge --panel-ip <IP панели> --open 2053
sudo ./tune-resilience.sh
sudo ./geodata-update.sh --install-timer
```

Или без клона, одной строкой на чистом сервере:

```bash
curl -fsSL https://raw.githubusercontent.com/ponoroshca/remnawave-node-kit/main/install-node.sh | sudo bash -s -- --secret <SECRET_KEY> --bridge
```

Уже работающая нода — ничего переустанавливать не нужно:

```bash
sudo ./tune-net.sh              # BBR — сразу, без рестарта
sudo ./tune-resilience.sh       # очередь приёма подхватится после docker restart remnanode
./health.sh                     # одна строка — что с узлом
```

Весь флот:

```bash
cp examples/nodes.txt nodes.txt && nano nodes.txt     # «имя ip» по строке
./fleet.sh nodes.txt health.sh
./fleet.sh nodes.txt probe-steal.sh
./fleet.sh -k ~/.ssh/id_ed25519 nodes.txt tune-resilience.sh -- --dry-run
```

## Безопасность

- `install-node.sh` **не трогает существующую установку**: если `/opt/remnanode` уже есть —
  останавливается; `--force` переписывает, сохранив старые `.env` и `compose` рядом с датой.
- Файрвол настраивается только с явным `--panel-ip`; ssh-порт определяется сам и открывается
  первым, чтобы не отрезать себя.
- `tune-*.sh` пишут только свои файлы в `/etc/sysctl.d/` с префиксом `node-kit` и умеют `--undo`.
- `geodata-update.sh` не подменяет списки, пока новые файлы не прошли проверку размера, и
  откатывает, если xray не поднялся за 90 секунд.
- Ни один скрипт не ходит в панель и не знает вашего API-токена. Ключ ноды попадает только
  в `/opt/remnanode/.env` с правами 600.

Подробно, по каждому файлу и команде отмены — [docs/SAFETY.md](docs/SAFETY.md).

## Совместимость

Ubuntu 22.04 / 24.04, Debian 12; Remnawave 2.x (`ghcr.io/remnawave/node`); root.
Нода **не должна быть новее панели** — при ошибках рукопожатия панель ↔ нода пиньте версию:
`--image ghcr.io/remnawave/node:2.8.0` (см. [faq](docs/faq.md)).
