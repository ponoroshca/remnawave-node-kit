# Мост с нуля за 5 минут

Мост — сервер в стране клиентов, который принимает их подключения и отдаёт трафик на
выходные ноды за границей. Выходная нода ставится теми же шагами, только без `--bridge`.

## Что нужно

- Чистый сервер: Ubuntu 22.04/24.04 или Debian 12, root по SSH. Для моста — в стране
  клиентов; 2 ядра и 2–4 ГБ памяти хватает на несколько сотен человек.
- Работающая панель Remnawave.

## Шаг 1. Создать ноду в панели и взять ключ

1. Панель → **Nodes** → **Create node**.
2. Имя (например `RF-1`), адрес — IP сервера, порт `3000`. Страну поставьте правильно —
   по ней потом удобно отбирать мосты.
3. Панель покажет **SECRET_KEY** — длинную строку (в разных версиях: сразу после создания,
   кнопка «Show key» в карточке ноды или «Node keys» на странице нод). Скопируйте целиком.
   Ключ один на все ваши ноды.

## Шаг 2. Одна команда на сервере

```bash
curl -fsSL https://raw.githubusercontent.com/ponoroshca/remnawave-node-kit/main/install-node.sh \
  | sudo bash -s -- --secret <SECRET_KEY> --bridge --panel-ip <IP панели> --open 2053
```

- `--bridge` — скачать списки маршрутизации (geodata) и подключить их в контейнер; для
  выходной ноды флаг не нужен;
- `--panel-ip` — закрыть порт `3000` для всех, кроме панели (ufw). Ваш ssh-порт скрипт найдёт
  сам и откроет первым;
- `--open 2053` — порты, на которых будут подключаться клиенты (перечислите через запятую те,
  что в ваших инбаундах).

Что вы увидите в конце:

```
RESULT rf-1: контейнер=[Up 8 seconds] xray=26.3.27 порт 3000 слушает=да
Дальше: в панели нода должна стать «на связи»; привяжите ей профиль и инбаунды. Здоровье: ./health.sh
```

Если вместо этого `СТОП: /opt/remnanode уже существует` — на сервере уже стоит нода;
скрипт ничего не тронул. Переписать с бэкапом старых файлов: добавьте `--force`.

## Шаг 3. В панели

Нода стала «на связи». Откройте её карточку → **Config profile** → выберите профиль и
инбаунды, которыми она должна отвечать. Для моста профиль обычно свой (с правилами, куда
какой трафик уходить), для выходной ноды — профиль с одним инбаундом.

## Шаг 4. Чтобы не падало под нагрузкой

```bash
sudo ./tune-resilience.sh      # conntrack, очередь приёма, watchdog, earlyoom
sudo docker restart remnanode  # очередь приёма xray читает при старте
```

Для моста — свежие списки раз в неделю с откатом при проблемах:

```bash
sudo ./geodata-update.sh --install-timer
```

## Шаг 5. Убедиться

```bash
./health.sh
./probe-speed.sh
./probe-steal.sh
```

`health.sh` даст строку вида `cores=2 cpu=12 st=0 retr=0.3 … rn=1 tx=48 rx=51` — `rn=1`
значит контейнер жив, `st` — steal (норма до 5), `ct` — заполнение conntrack в процентах.
`probe-speed.sh` покажет, сколько канала реально доступно; `probe-steal.sh` — не перепродан
ли сервер. Что означают остальные числа — в шапке `health.sh`.

## Если что-то не так

| вы видите | что это значит | что сделать |
|---|---|---|
| `нужен ключ ноды` | не передали `--secret` | скопируйте SECRET_KEY из панели |
| `порт 3000 слушает=НЕТ` и в логе `Please fix your .env file` | ключ неверный или обрезан | скопируйте SECRET_KEY целиком и запустите с `--force` |
| `geodata: … НЕ СКАЧАЛСЯ` | с этого сервера не тянется GitHub | скачайте файл на другой машине и положите в `/var/lib/remnanode/`, запустите снова |
| нода в панели «не на связи» | панель не достаёт до порта 3000 | `--panel-ip` указан верно? хостер не закрыл порт? `ss -ltn \| grep 3000` |
| ошибка рукопожатия панель ↔ нода в логах | нода новее панели | `--force --image ghcr.io/remnawave/node:<версия панели>` |
| `probe-speed` показывает 0 | источник замера недоступен с сервера | попробуйте свой: `SRC_EU=https://… ./probe-speed.sh` |
| `steal 30%` | хостер перепродал сервер | тариф выше или другой хостер; мост с таким steal «рвёт» видео |
